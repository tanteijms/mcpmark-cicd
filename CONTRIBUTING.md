# Contributing to mcpmark-cicd

Thank you for your interest in contributing to this project! We welcome contributions from everyone.

## How to Contribute

We appreciate all contributions, whether they are bug fixes, new features, documentation improvements, or other enhancements.

### Getting Started

1. **Fork** the repository to your GitHub account
2. **Clone** your fork locally: `git clone https://github.com/YOUR_USERNAME/mcpmark-cicd.git`
3. **Create a branch** for your changes: `git checkout -b feature/your-feature-name`
4. **Make your changes** and commit them with clear, descriptive messages
5. **Push** your branch to your fork: `git push origin feature/your-feature-name`
6. **Open a Pull Request** from your branch to the main repository's `main` branch

## Code of Conduct

This project adheres to the [Contributor Covenant Code of Conduct](https://www.contributor-covenant.org/). By participating, you are expected to uphold this code. Please report any unacceptable behavior to the maintainers.

All contributors must:
- Be respectful and inclusive in all interactions
- Welcome newcomers and help them get started
- Accept constructive criticism gracefully
- Focus on what is best for the community

## Contribution Workflow

### Fork and Branch
- Always work from a feature branch, never directly on `main`
- Branch naming convention: `feature/description`, `fix/description`, `docs/description`

### Pull Requests
- Provide a clear description of what your PR does and why
- Reference any related issues using `#issue-number`
- Ensure all tests pass before requesting review
- Keep PRs focused and small when possible

### Style Guide
- Follow the existing code style and formatting rules
- Run linting and formatting tools before committing
- Write clear, self-documenting code with comments where needed
- Follow naming conventions established in the codebase

## Reporting Issues

When reporting bugs or requesting features:
- Search existing issues first to avoid duplicates
- Use the appropriate issue template
- Provide as much detail as possible
- Include steps to reproduce for bugs

## Questions?

Feel free to open an issue or reach out to the maintainers for any questions about contributing.
